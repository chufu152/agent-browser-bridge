# Universal Browser Agent（UBA）项目概述

| 项目属性 | 内容 |
|---|---|
| 项目类型 | 通用 AI 浏览器控制插件与接入基础设施 |
| 文档版本 | V1.0 |
| 文档日期 | 2026-11-19 |
| 当前阶段 | 项目规划，暂不进入实现 |
| 核心定位 | 让任意 AI Agent 通过统一接口，直接控制用户授权的真实浏览器 |

## 1. 项目背景

现有视觉型浏览器 Agent 通常依赖“截图—识别—坐标预测—模拟点击”的闭环。该路径在元素密集、页面动态变化或布局偏移时容易失效，并带来额外的图像传输和识别开销。

UBA 采用浏览器插件与页面直接交互的方式，将页面读取、元素定位、原生交互、标签页管理和页面状态监听封装为标准能力。Agent 只负责理解用户意图和规划任务，不需要了解网页内部结构或插件实现。

## 2. 项目目标

### 2.1 总体目标

建立一个模型无关、Agent 无关、接口统一的浏览器控制层，使不同 Agent 能使用同一套指令完成浏览器任务。

### 2.2 具体目标

1. **直接读取页面**：向 Agent 提供结构化页面快照、可交互元素和必要的可见文本。
2. **直接执行操作**：通过元素引用或语义定位完成点击、输入、选择、滚动、导航等操作。
3. **统一接入协议**：所有 Agent 共用同一套方法、参数、结果和错误语义。
4. **支持多 Agent**：隔离不同 Agent 的会话、标签页权限、事件订阅和审计记录。
5. **降低执行开销**：通过快照缓存、元素引用复用、增量变化、批量操作和智能等待减少重复工作。
6. **保护用户控制权**：默认本地接入、最小权限、敏感信息保护和高风险操作人工确认。
7. **可恢复与可诊断**：面对页面导航、元素失效、插件后台休眠或连接中断，能够返回明确状态并安全恢复。

## 3. 核心能力

### 3.1 页面理解

- 提取页面地址、标题、可见文本和交互元素。
- 识别元素角色、可访问名称、输入提示、标签、禁用和可见状态。
- 为元素生成绑定页面文档和元素身份的短期引用；无关页面变化后可复核复用，导航或元素替换后失效。
- 支持完整快照和按页面版本获取增量变化。
- 按需读取，避免默认传输整页内容。

### 3.2 元素定位与页面操作

- 支持元素引用、角色与名称、文本、标签、输入提示、CSS 选择器和路径表达式等定位方式。
- 优先使用稳定语义定位，结构定位作为补充。
- 支持点击、填写、逐字输入、清空、按键、悬停、勾选、选择选项和滚动到可见区域。
- 支持前进、后退、刷新、跳转、读取页面信息和等待页面状态。
- 操作后检查实际页面状态；禁止仅修改元素属性就报告成功。

### 3.3 标签页管理

- 获取当前及全部标签页。
- 创建、切换和关闭标签页。
- 将标签页分配给指定 Agent 会话，并阻止越权访问。
- 在导航、关闭或标签页状态变化后更新上下文。

### 3.4 页面观察与智能等待

- 监听元素新增、删除、文本和属性变化。
- 通过事件订阅或变化查询通知 Agent。
- 根据导航、目标元素和页面变化判断等待条件，不采用固定延时作为主要同步机制。

### 3.5 通用 Agent 接入

- 提供统一浏览器控制协议。
- 通过本地通信服务、标准工具适配层和 SDK 接入不同 Agent。
- 适配层只转换协议，不重复实现页面解析、定位或操作引擎。
- 不内置或绑定特定模型供应商。

## 4. 典型使用场景

| 场景 | 用户意图示例 | UBA 执行路径 |
|---|---|---|
| 页面检索 | “在当前站点搜索某关键词并打开结果” | 获取快照 → 定位搜索框 → 填写 → 点击 → 等待导航 |
| 表单辅助 | “填写这页的基本资料，但不要提交” | 读取字段 → 逐项填写 → 校验状态 → 停在提交前 |
| 多标签页任务 | “打开两个页面并比较可见信息” | 创建标签页 → 分别读取 → 按权限汇总结果 |
| 动态页面监控 | “目标内容出现后告诉我” | 订阅页面变化 → 接收增量事件 → 检查目标文本 |
| 自定义 Agent 接入 | “让我的本地 Agent 使用当前浏览器” | 本地认证 → 建立会话 → 调用统一协议 |
| 批量页面操作 | “依次填写这些字段并勾选选项” | 提交有序批量指令 → 逐项执行 → 返回逐项结果 |

## 5. 关键约束

### 5.1 执行路径约束

1. 默认且主要的执行路径必须是结构化页面读取和直接页面操作。
2. 不得以“Agent 在后台识别截图后预测坐标并模拟点击”作为默认方案。
3. 截图可用于测试取证或未来独立评估的补充能力，但不得成为常规操作的前置依赖。
4. 不通过伪造成功结果、绕过页面逻辑或直接篡改业务数据来代替真实交互。

### 5.2 接入与边界约束

- 默认只接受本机、经过身份认证的 Agent。
- 不将浏览器控制端口直接暴露到公网。
- Agent 不获取浏览器 Cookie、登录令牌、密码字段或其他凭据。
- 不支持绕过登录墙、付费墙、验证码或站点安全控制。
- 不开放无约束的任意脚本执行能力。
- 支付、删除、发送、发布、账户安全修改等高风险操作必须由用户在浏览器侧明确确认。

### 5.3 浏览器平台约束

- 插件后台运行环境可能休眠，状态必须可重建。
- 页面重绘、导航和动态组件会使元素引用失效，必须支持重新定位。
- 浏览器内部页面、扩展商店等特殊页面可能无法注入，必须明确返回“不支持”。
- 跨域框架、阴影 DOM、画布类交互和需要用户手势的能力需要单独处理或声明限制。
- 第三方站点改版可能影响定位，应优先使用语义信息并保留诊断入口。

## 6. 非目标

首版明确不做以下事项：

- 不在插件中内置大模型或任务规划器。
- 不替换用户现有浏览器或强制使用独立自动化浏览器。
- 不保证所有网站、所有自定义组件均可自动化。
- 不默认执行文件上传下载、支付、发布或账户安全修改。
- 不提供无人监督的高风险操作模式。
- 不以远程公网控制作为首版能力。
- 不让不同 Agent 适配器各自实现一套浏览器控制引擎。

## 7. 角色与职责

| 角色 | 职责 | 明确不负责 |
|---|---|---|
| 用户 | 授权站点与标签页、确认高风险操作、管理 Agent 访问 | 不需要理解协议细节 |
| Agent | 理解自然语言、规划任务、调用结构化指令、处理结果 | 不直接注入页面、不自行审批高风险操作 |
| 接入层 | 认证、会话、路由、限流、超时、隔离和审计 | 不理解自然语言、不解析 DOM |
| 插件控制层 | 管理标签页、调度页面命令、维护页面上下文 | 不绑定特定 Agent |
| 页面执行层 | 快照、定位、操作、观察和状态核验 | 不持有用户凭据、不做任务规划 |

## 8. 成功标准

以下为首版验收基线。性能数值适用于项目定义的受控标准页面与本地环境，页面自身网络和渲染耗时须单独记录。

### 8.1 功能成功标准

- 标准功能测试集中的页面读取、定位、点击、填写、选择、滚动和导航用例全部通过。
- 所有常规功能用例均不依赖截图识别或坐标预测。
- 页面操作结果包含真实状态核验；失败时返回可识别的错误类型。
- 元素因页面变化失效时，不会误操作其他元素。

### 8.2 开放性成功标准

- 至少两个独立实现的 Agent 能通过同一协议完成同一条浏览器任务。
- 新 Agent 只需实现协议适配，不需要修改页面执行引擎。
- 协议具备版本标识，未知方法和未知字段有可预测的处理方式。

### 8.3 性能成功标准

- 标准页面完整快照生成的第 95 百分位耗时不超过 1 秒。
- 本地简单页面操作的插件执行耗时第 95 百分位不超过 300 毫秒，不含页面业务响应时间。
- 页面无有效变化时能够命中快照缓存，并避免重复完整解析。
- 批量操作按顺序返回逐项结果，出错时按策略停止，不产生静默跳过。

### 8.4 安全成功标准

- 未认证、已撤销和越权访问请求全部被拒绝。
- 高风险操作未经用户确认时执行成功数为零。
- 密码、Cookie、令牌和认证信息不出现在协议响应及普通审计日志中。
- Agent 无法通过接口自行批准自己的高风险请求。

### 8.5 可靠性成功标准

- 插件后台休眠恢复、通信服务重启或 Agent 断连后，不会重复执行结果未知的非幂等操作。
- 页面导航、标签页关闭和元素失效均有明确错误与恢复路径。
- 多 Agent 并行时，会话、事件和标签页权限不发生串用。

## 10. 后续决策原则

进入实现前，所有技术选型必须满足以下顺序：安全边界优先，其次为直接页面操作能力、协议兼容性和可恢复性，最后才是工程便利性。任何引入截图、远程接入或更高权限的变更，都必须单独评估并更新架构、接口与测试文档。
