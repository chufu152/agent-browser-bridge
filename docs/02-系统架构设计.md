# Universal Browser Agent（UBA）系统架构设计

| 文档属性 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 文档日期 | 2026-11-19 |
| 架构状态 | 规划基线 |
| 设计范围 | 插件端、Agent 接入层、指令解析与执行、安全边界、主要数据流 |
| 技术栈约束 | 本文只定义逻辑组件和职责，不指定实现框架 |

## 1. 架构目标与原则

### 1.1 架构目标

将任意 Agent 的结构化请求转换为对用户真实浏览器的可审计操作，并把页面状态以统一、最小、可恢复的形式返回给 Agent。

### 1.2 核心原则

1. **思考与执行解耦**：Agent 负责自然语言和任务规划；系统只接收结构化指令。
2. **直接页面操作**：默认通过 DOM 和浏览器扩展能力执行，不以后台截图识别和坐标预测为主路径。
3. **单一控制引擎**：所有接入方式共用快照、定位、操作、观察和标签页能力。
4. **最小权限**：按 Agent、会话、标签页、方法和操作风险授权。
5. **状态可恢复**：插件后台和通信服务均可重启，关键状态不依赖长期内存变量。
6. **显式结果**：所有命令必须成功、失败或等待用户确认，不允许模糊完成。
7. **按需传输**：优先返回结构化元素和变化，不默认发送整页内容。

## 2. 总体逻辑架构

```text
用户自然语言指令
        |
        v
Agent（理解、规划、调用）
        |
        | 统一浏览器控制协议
        v
Agent 接入层
  - 标准工具适配
  - SDK 适配
  - 本地连接接入
        |
        v
本地通信与治理层
  - 身份认证 / 会话管理 / 请求路由
  - 权限检查 / 限流 / 超时 / 审计
        |
        | 本地受控通信
        v
插件控制层
  - 指令校验 / 风险分类 / 执行编排
  - 标签页管理 / 页面上下文 / 事件分发
        |
        | 扩展内部受控消息
        v
页面执行层
  - 快照 / 定位 / 操作 / 观察 / 状态核验
        |
        v
用户真实浏览器与已授权网页
```

### 2.1 推荐架构决策

采用“页面执行组件 + 插件控制组件 + 本地通信桥接”的分层架构。原因是需求同时包含跨标签页状态、多 Agent 双向通信、权限治理和页面 DOM 操作，单一页面脚本无法承担全部职责。

备选方案是 Agent 直接连接插件，但会把认证、路由、会话隔离和审计分散到不同接入实现中，因此不作为推荐方案。

## 3. 组件职责

### 3.1 Agent 接入层

| 组件 | 主要职责 | 边界 |
|---|---|---|
| 标准工具适配器 | 将浏览器能力暴露为 Agent 可发现的工具 | 只转换协议，不实现 DOM 逻辑 |
| SDK 接口 | 提供统一调用、错误和事件模型 | 不绕过认证和权限检查 |
| 连接接入器 | 接收本地 Agent 请求并返回响应或事件 | 不直接访问网页 |

所有适配器必须映射到同一浏览器控制协议，不得各自维护定位规则和操作语义。

### 3.2 本地通信与治理层

| 组件 | 职责 |
|---|---|
| 连接管理 | 建立、维持和关闭 Agent 连接，识别异常断连 |
| 身份认证 | 校验 Agent 身份和本地令牌，支持更新与撤销 |
| 会话管理 | 建立会话上下文，绑定 Agent、标签页和订阅关系 |
| 请求路由 | 将统一方法映射到插件控制层，关联请求与响应 |
| 权限治理 | 执行方法权限、标签页权限、速率限制和风险策略 |
| 超时与取消处理 | 管理请求生命周期，断连后停止尚未开始的安全操作 |
| 审计 | 记录必要的操作元数据、结果和人工确认，不记录敏感内容 |

本地通信与治理层不解析自然语言，不读取网页 DOM，也不自行决定是否执行高风险操作。

### 3.3 插件控制层

| 组件 | 职责 |
|---|---|
| 指令校验器 | 校验协议版本、会话、方法、参数、标签页和请求状态 |
| 风险分类器 | 综合方法、目标页面、元素语义和动作判断风险等级 |
| 执行编排器 | 管理单步、批量、等待、导航和结果汇总 |
| 标签页管理器 | 枚举、创建、切换、关闭和分配标签页 |
| 页面上下文管理器 | 维护页面版本、导航状态、快照和元素引用映射 |
| 事件分发器 | 将页面和标签页事件只发送给有权限的订阅者 |
| 用户确认管理器 | 在浏览器侧展示风险摘要并接收用户决定 |
| 状态恢复管理器 | 在后台休眠或重启后重建会话映射与可恢复状态 |

### 3.4 页面执行层

#### DOM 与快照组件

- 只读取当前用户页面中可见且被授权的内容。
- 提取交互元素的角色、名称、文本、标签、输入提示和状态。
- 排除密码和敏感输入内容；默认不返回完整页面源码。
- 为快照分配单调递增或可比较的页面版本。
- 支持完整快照、增量变化和缓存失效。

#### 定位组件

- 支持引用定位与语义定位，并允许结构和路径定位作为补充。
- 一个定位条件若匹配多个元素，应返回歧义错误，而不是任意选择。
- 引用绑定页面文档和元素身份，快照版本用于变化检测；导航或元素替换后必须重新定位。
- 同一文档发生无关 DOM 变化时，未变化的元素引用可继续使用，但操作前必须重新核验元素身份、可见性和可用性。
- 操作前再次检查可见性、可用性和元素身份，防止误操作。

#### 操作组件

- 执行真实页面交互，包括必要的焦点、输入、变更和键盘行为。
- 操作后检查元素值、选中状态、页面导航或预期变化。
- 区分“指令已发送”和“页面已达到目标状态”，最终响应必须基于后者。
- 无法核验时返回状态未知或核验失败，不得直接报告成功。

#### 页面观察组件

- 监听元素、文本和属性的有效变化。
- 对高频变化进行合并，并为每个会话维护统一事件顺序和游标；订阅只决定过滤范围。
- 只向 Agent 返回其订阅范围内的变化。
- 发现事件缺口时要求重新获取快照或变化列表。

## 4. 指令解析与执行流程

“指令解析”指结构化协议解析，不是自然语言理解。自然语言到方法序列的转换完全属于 Agent。

### 4.1 单条指令处理管线

1. **接入检查**：校验连接来源、协议版本和请求外层结构。
2. **身份与会话检查**：校验 Agent 身份、凭据和会话是否有效。
3. **方法授权检查**：检查 Agent 是否具有该方法能力。
4. **参数校验**：检查请求标识、方法参数、超时和分页参数是否合法。
5. **目标检查**：检查标签页权限、页面支持状态和导航状态。
6. **预定位与风险分类**：对元素操作先定位并读取目标语义，再结合方法、目标站点和动作判定普通、受限或高风险。
7. **人工确认**：高风险操作返回待确认状态，由用户在浏览器侧决定；确认后须由 Agent 重新提交原操作。
8. **执行前复核**：重新检查会话、权限、操作指纹、页面文档、元素身份、可见性和可用性；确认操作还需核对确认有效期。
9. **实际执行**：调用浏览器或页面能力，并观察必要的页面状态。
10. **结果核验**：检查目标状态，记录页面版本、导航和变化信息。
11. **响应与审计**：返回结构化结果或标准错误，记录不含敏感值的审计元数据。

任一步失败都必须终止当前指令的后续阶段；批量指令则按批量策略决定是否继续。风险分类不能只发生在批次开始时，每个动作执行前都必须重新分类。

### 4.2 批量执行

- 默认顺序执行，前序结果可供用户审计，但不允许动态拼接未校验的任意指令。
- 默认遇错停止，并明确标记未执行项。
- 返回每一项的执行状态，不能只返回整体“成功”。
- 批次开始前对当前可定位动作做风险预扫描；已能识别的高风险动作导致整批在执行前被拒绝。
- 每个动作执行前重新定位并分类风险。若前序动作改变了后续风险，系统必须在高风险动作执行前停止：保留已执行项结果，当前项标记为 `blocked`，后续项标记为 `skipped`，并要求 Agent 获取新快照后单独提交高风险动作。
- 高风险动作不得隐藏在批量命令中；首版要求高风险动作独立提交并独立确认。
- 元素引用可跨无关快照版本复用，但每次使用前必须复核同一文档和元素身份；引用失效由当前项返回错误。
- 批量不等于事务，无法承诺跨页面操作自动回滚，响应中必须明确这一点。

### 4.3 智能等待

等待条件按优先级使用：导航完成信号、目标元素出现或可达、目标文本出现、页面状态稳定。超时应返回最后已知页面版本和可诊断原因，不通过无限延长等待掩盖失败。

## 5. 权限与安全边界

### 5.1 信任边界

| 边界 | 不可信输入 | 必要控制 |
|---|---|---|
| Agent → 接入层 | 方法、参数、来源、会话和重试请求 | 本机限制、认证、格式校验、限流 |
| 接入层 → 插件 | 路由后的命令和标签页范围 | 二次鉴权、会话校验、请求关联 |
| 插件 → 网页 | 定位条件、输入值和交互动作 | 页面支持检查、风险分类、真实状态核验 |
| 网页 → Agent | 页面文本、元素名称和事件 | 敏感过滤、按需返回、不可信内容标记 |
| 系统 → 用户 | 高风险确认摘要 | 清晰目标、动作、站点和不可逆提示 |

页面内容应被视为不可信数据。页面中的“忽略之前规则”等文本只能作为页面内容返回，不能改变系统权限或触发额外指令。

### 5.2 操作分级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| 普通 | 读取可见页面、查找元素、滚动、普通导航、切换已授权标签页 | 认证和方法授权后执行 |
| 受限 | 文件传输、敏感站点读取、重要表单填写、关闭标签页 | 显式授权，必要时按次确认 |
| 高风险 | 支付、删除、发送、发布、修改账户安全设置、最终提交重要表单 | 每次由用户在浏览器侧确认 |

风险分类必须结合动作语义和目标站点，不能只依赖方法名。例如普通点击方法点击“确认支付”时仍属于高风险。

### 5.3 身份与会话

- 每个 Agent 使用独立身份和可撤销凭据。
- 会话绑定 Agent、授权标签页、协议版本和过期时间。
- 标签页授权不随另一个 Agent 的会话自动共享。
- 凭据不出现在页面快照、事件和普通日志中。
- 远程 Agent 不在首版默认开放；未来开放时必须使用经过认证的安全通道，不得直接暴露本地控制接口。

### 5.4 敏感信息与审计

- 默认不读取密码字段值，不返回 Cookie、浏览器令牌或账户凭据。
- 对可能的敏感文本采用最小返回和字段过滤。
- 审计记录包含时间、Agent、会话、方法、目标站点、风险级别、结果和确认结果。
- 审计记录默认不包含完整输入值、页面全文和认证参数。
- 日志应有保留期限和用户清理入口。

## 6. 主要数据流

### 6.1 页面读取流

```text
Agent 请求快照
→ 接入层认证和会话检查
→ 插件检查标签页权限
→ 页面执行层检查缓存与页面版本
→ 无有效缓存则解析可见 DOM
→ 过滤敏感内容并生成元素引用
→ 返回页面信息、元素列表、版本和截断标记
```

### 6.2 页面操作流

```text
Agent 提交操作
→ 格式、身份、会话和权限检查
→ 预定位目标元素并完成风险分类
→ 必要时进入人工确认及重新提交流程
→ 执行前复核目标元素
→ 执行真实交互
→ 观察操作后的元素或导航状态
→ 更新快照与引用缓存
→ 返回操作结果、页面版本和必要变化
```

### 6.3 高风险操作流

```text
Agent 使用操作编号提交高风险操作
→ 系统预定位并生成风险摘要和确认编号
→ 原请求返回“需要确认”，操作进入等待确认状态
→ 浏览器侧向用户展示目标站点、动作和对象
→ 用户确认或拒绝，系统发布确认结果事件
→ 若已确认，Agent 以相同操作编号、相同参数和确认编号重新提交
→ 系统重新校验会话、权限、页面文档、元素身份、操作指纹和确认有效期
→ 全部有效才执行；否则确认失效且不执行
→ 返回最终结果并记录确认审计
```

Agent 只能接收确认状态，不能调用接口代替用户确认。用户确认后系统不会自动执行，必须等待 Agent 重新提交；重新提交通过操作去重机制返回同一次操作的最终结果，不能创建第二次业务动作。无关 DOM 变化不自动使确认失效，但页面文档、目标元素、站点、动作或参数变化必须使原确认失效。用户拒绝后，重新提交返回 `CONFIRMATION_DENIED`。

### 6.4 页面事件流

```text
页面发生变化
→ 观察组件合并并生成有序事件
→ 插件按标签页权限过滤
→ 接入层按会话和订阅关系分发
→ Agent 接收事件或主动查询变化
→ 若序号不连续，Agent 重新同步页面状态
```

### 6.5 断连与恢复流

- 已完成的操作按 `operationId` 保留短期结果，Agent 通过 `browser.getOperation` 查询；相同标识携带不同参数必须拒绝。
- 尚未开始的普通操作可在断连时取消。
- 已开始且结果未知的非幂等操作不得自动重放。
- Agent 断连即终止原会话及其订阅；原会话的事件游标和确认编号失效。
- 同一 Agent 重新认证后建立新会话，可查询自己此前的操作结果，但必须重新订阅并获取完整快照。
- 插件后台恢复后重新读取标签页与页面状态，旧引用和旧确认默认失效。

## 7. 多 Agent 隔离

1. 会话隔离：请求只在其会话上下文内有效。
2. 标签页隔离：未授权标签页对 Agent 不可见或不可操作。
3. 事件隔离：事件只发送给匹配订阅的所有者。
4. 缓存隔离：共享只读缓存不得泄露其他 Agent 的过滤后数据或私有上下文。
5. 审计隔离：记录可按 Agent 和会话检索。
6. 资源隔离：单 Agent 的批量任务、订阅数和请求速率不得阻塞其他 Agent。

## 8. 性能与一致性设计

- 快照以页面版本为缓存键的一部分，导航、重大 DOM 变化和标签页切换后重新校验。
- 元素引用是短期定位优化，不是永久标识；失效后返回明确错误。
- 增量事件携带序号，允许 Agent 发现丢失并重新同步。
- 批量操作减少通信往返，但不牺牲逐项权限与结果检查。
- 高频 DOM 变化需要合并和限流，避免事件量大于完整快照的收益。
- 所有性能优化都不得绕过敏感过滤、风险确认或操作后核验。

## 9. 可恢复状态与数据分类

| 数据 | 生命周期 | 恢复要求 |
|---|---|---|
| Agent 配置与授权 | 用户撤销前有效 | 重启后保留，可撤销 |
| 会话与订阅 | 断连、撤销或过期时终止 | 重连后新建会话和订阅，旧事件游标不得复用 |
| 页面快照 | 受页面版本控制 | 可丢弃并重建 |
| 元素引用 | 同一文档和元素身份内短期有效 | 无关版本变化后复核复用；导航或元素替换后重新定位 |
| 用户确认 | 单次、短时、绑定会话与操作指纹 | 无关 DOM 变化后复核；文档、目标、参数或会话变化后失效 |
| 请求结果 | 默认 15 分钟短期去重窗口 | 跨本地服务和插件重启保留；通过 `browser.getOperation` 查询，防止重复执行非幂等操作 |
| 审计记录 | 按保留策略管理 | 重启后仍可追溯 |

## 10. 平台限制与降级策略

| 限制 | 系统行为 |
|---|---|
| 特殊浏览器页面不可注入 | 返回不支持错误，不尝试绕过 |
| 跨域框架 | 首版明确范围；不能访问时指出框架限制 |
| 阴影 DOM | 按阶段支持；不支持时不得误报页面无元素 |
| 画布和非 DOM 交互 | 声明无法通过常规 DOM 路径完成，视觉补充另行评审 |
| 用户手势限制 | 请求用户介入或返回权限/状态错误 |
| 站点反自动化或频繁改版 | 不规避安全控制；通过语义定位和诊断提高可维护性 |
| 插件后台休眠 | 从持久状态恢复，不让旧内存状态成为唯一依据 |

## 11. 架构验收检查表

- 所有接入路径均汇聚到同一指令校验、权限和执行管线。
- 常规读取和操作不存在截图识别或坐标预测依赖。
