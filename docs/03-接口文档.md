# Universal Browser Agent（UBA）接口文档

| 文档属性 | 内容 |
|---|---|
| 协议名称 | Browser Control Protocol（BCP） |
| 协议版本 | V1.0（规划基线） |
| 文档日期 | 2026-11-19 |
| 报文基础 | JSON-RPC 2.0 |
| 接入方式 | 本地双向通信、标准工具适配、SDK；均映射到同一协议 |
| 文档范围 | 接入、指令、结果、权限、错误、批量和异步事件 |

## 1. 接口目标与通用约定

BCP 是 Agent 与浏览器控制系统之间的唯一业务协议。标准工具适配器和 SDK 不得定义另一套页面操作语义。

### 1.1 基本约定

- 默认只接受本机连接，连接来源必须经过校验。
- 每次连接必须完成身份认证并建立会话。
- 所有请求使用 UTF-8 编码的 JSON 报文。
- 请求 `id` 在单个连接内唯一；通知不包含 `id`。
- 方法名区分大小写，采用 `命名空间.动作` 形式。
- 时间使用带时区的标准时间文本；耗时使用毫秒。
- 所有写操作必须明确目标标签页，不得依赖不确定的“当前页面”。
- 未知必填字段、无效字段类型和不受支持的协议版本必须被拒绝。
- 为保证向前兼容，接收方可忽略明确标记为可选的未知扩展字段，但不得改变已有字段语义。

### 1.2 通用标识

| 字段 | 含义 | 生命周期 |
|---|---|---|
| `agentId` | Agent 的稳定身份 | 凭据撤销前有效 |
| `sessionId` | 一次已认证会话 | 断连、撤销、显式关闭或过期时失效；重连须建立新会话 |
| `tabId` | 浏览器标签页标识 | 标签页关闭后失效 |
| `operationId` | 客户端操作标识 | 在同一 Agent 内唯一，用于去重、审计和安全查询 |
| `ref` | 不透明元素引用 | 绑定页面文档和元素身份；导航或元素替换后失效 |
| `snapshotVersion` | 页面快照版本 | 页面有效变化后更新 |
| `subscriptionId` | 事件订阅标识 | 取消订阅或会话结束后失效 |
| `confirmationId` | 单次人工确认标识 | 单次、短时且绑定操作指纹 |

`ref` 和 `confirmationId` 对 Agent 均为不透明值，不得根据格式推断内部信息。

## 2. 接入与会话

### 2.1 支持的接入形态

| 接入形态 | 用途 | 协议要求 |
|---|---|---|
| 本地双向通信 | 自定义 Agent 实时调用和接收事件 | 直接承载 BCP 请求、响应和通知 |
| 标准工具适配层 | 让支持工具发现的 Agent 自动获取浏览器能力 | 每个工具映射到一个或一组 BCP 方法 |
| SDK | 简化连接、请求、错误和事件处理 | 不绕过 BCP，不内置另一套执行引擎 |

首版不开放未经认证的远程访问，不允许网页直接调用高权限控制接口。

### 2.2 连接认证

连接建立时提供以下信息；认证材料通过连接的安全元数据传递，不放入普通业务参数和审计日志。

| 字段 | 必填 | 说明 |
|---|---|---|
| `agentId` | 是 | 已登记的 Agent 身份 |
| `token` | 是 | 独立、可撤销的本地访问凭据 |
| `protocolVersion` | 是 | 客户端支持的 BCP 主版本 |
| `clientName` | 否 | 便于用户识别的名称 |
| `requestedCapabilities` | 否 | 请求使用的能力列表 |

认证成功后返回：

| 字段 | 说明 |
|---|---|
| `sessionId` | 新会话标识 |
| `protocolVersion` | 实际协商版本 |
| `grantedCapabilities` | 实际授权能力 |
| `sessionExpiresAt` | 会话过期时间 |
| `serverTime` | 服务端当前时间 |

认证失败不得泄露令牌是否正确、Agent 是否存在等多余信息。令牌撤销后，已有会话必须在规定时间内失效。Agent 断连、本地通信服务重启或会话过期均终止会话及其订阅；重连后重新认证并创建新会话，同一 Agent 可使用原 `operationId` 查询自己的历史操作结果，但不能复用旧会话、订阅、事件游标或确认编号。

## 3. 请求与结果格式

### 3.1 标准请求

```json
{
  "jsonrpc": "2.0",
  "id": "req_001",
  "method": "browser.getSnapshot",
  "params": {
    "sessionId": "ses_123",
    "tabId": 123,
    "options": {
      "includeText": true,
      "maxElements": 200
    }
  }
}
```

所有方法的 `params` 都必须是对象。所有写操作和批量操作必须携带 `operationId`，且在同一 Agent 内唯一；只读方法不需要该字段。超时可通过 `timeoutMs` 指定，但系统可设置上限。

### 3.2 成功响应

```json
{
  "jsonrpc": "2.0",
  "id": "req_001",
  "result": {
    "url": "https://example.com",
    "title": "Example",
    "snapshotVersion": "sv_42",
    "elements": [
      {
        "ref": "el_001",
        "role": "textbox",
        "name": "搜索",
        "placeholder": "请输入关键词",
        "tag": "input",
        "type": "text",
        "disabled": false,
        "visible": true,
        "enabled": true
      }
    ],
    "truncated": false,
    "meta": {
      "requestId": "req_001",
      "durationMs": 36,
      "cacheHit": false
    }
  }
}
```

`meta` 为可选诊断信息，不得包含敏感页面内容或凭据。

### 3.3 通用操作结果

元素和页面写操作成功后，结果至少包含：

| 字段 | 说明 |
|---|---|
| `operationId` | 必须与写操作请求中的客户端操作标识一致 |
| `tabId` | 实际操作的标签页 |
| `status` | 固定为 `completed` |
| `snapshotVersion` | 操作后的页面版本，可获取时必填 |
| `navigation` | 是否发生导航及相关状态 |
| `verified` | 是否已核验目标页面状态 |
| `completedAt` | 完成时间 |

无法完成状态核验时不得返回 `completed` 且 `verified: true`。

### 3.4 操作去重与结果查询

- `operationId` 在同一 Agent 的所有会话中必须唯一，作用域不随断连改变。
- 系统为操作保存参数指纹、状态和最终结果。默认去重窗口为 15 分钟，实际值可由 `browser.getInfo` 返回；窗口内结果必须跨本地服务和插件重启保留。
- `browser.getOperation` 是只读查询，返回 `processing`、`waiting_confirmation`、`confirmed_pending_retry`、`completed`、`failed` 或 `unknown`，以及对应的原操作结果或标准错误；批量操作还需返回逐项状态。
- `confirmed_pending_retry` 表示用户已确认且系统尚未执行，Agent 应使用原 `operationId`、相同参数和有效 `confirmationId` 重新提交；只有该状态允许进入高风险续执行分支。用户拒绝则状态为 `failed`，原错误为 `CONFIRMATION_DENIED`。
- 相同 Agent 使用相同 `operationId` 和相同参数重发请求时：已完成返回原结果，处理中返回 `DUPLICATE_OPERATION`，等待确认返回原 `CONFIRMATION_REQUIRED`，失败返回原错误，状态未知返回 `OPERATION_OUTCOME_UNKNOWN`，均不得再次执行。
- `confirmed_pending_retry` 状态只有携带有效 `confirmationId` 才能续执行；缺少或伪造确认编号时返回 `PERMISSION_DENIED`，不得执行。
- 相同 `operationId` 携带不同参数时返回 `OPERATION_ID_CONFLICT`。
- 高风险操作在用户确认后的重新提交是上述去重规则的唯一续执行分支，必须同时提供有效 `confirmationId`。
- 超出保留窗口后，Agent 不得假设系统仍能去重；对结果未知的非幂等操作仍不得自动重试。

## 4. 通用定位与快照模型

### 4.1 定位对象

定位对象必须且只能包含一种主定位策略：

```json
{
  "role": "button",
  "name": "搜索"
}
```

| 策略字段 | 附加条件 | 说明 |
|---|---|---|
| `ref` | 无 | 绑定文档和元素身份；每次执行前复核 |
| `role` + `name` | 可带 `exact` | 首选语义定位 |
| `text` | 可带 `exact` | 匹配可见文本 |
| `label` | 无 | 匹配关联标签 |
| `placeholder` | 无 | 匹配输入提示 |
| `selector` | 无 | 结构定位，作为补充 |
| `xpath` | 无 | 路径定位，作为补充 |

`locator.find` 是查询操作：零匹配返回空列表，多匹配返回匹配列表和 `ambiguous: true`。其他定位执行方法要求唯一目标：零匹配返回 `ELEMENT_NOT_FOUND`，多匹配返回 `AMBIGUOUS_LOCATOR`，不得任意选择。执行前发现元素不可见或不可用，应返回对应状态错误。

`snapshotVersion` 更新不自动使 `ref` 失效。同一文档发生无关变化时，系统复核元素身份后可继续使用引用；导航、文档替换或元素身份变化后返回 `STALE_ELEMENT_REFERENCE`。批量中的每个引用都在对应动作执行前独立复核。

### 4.2 快照选项

| 字段 | 默认值 | 说明 |
|---|---|---|
| `includeText` | `false` | 是否返回必要的可见文本 |
| `maxElements` | 系统默认值 | 限制元素数量，避免整页无差别传输 |
| `sinceVersion` | 无 | 提供时优先返回基于该版本的变化 |
| `includeAccessibilityTree` | `false` | 是否附带可访问性结构 |

快照必须包含 `truncated`。版本过旧或无法计算增量时，返回完整快照并标记 `fullSync: true`。

## 5. 方法定义

以下方法均需在 `params` 中携带有效 `sessionId`。涉及具体页面的方法还需携带 `tabId`；`browser.createTab`、`browser.getOperation`、`browser.getEvents` 和仅使用 `subscriptionId` 的 `page.unsubscribe` 等方法属于例外。

### 5.1 Browser 方法

| 方法 | 关键参数 | 成功结果 |
|---|---|---|
| `browser.getInfo` | 无 | 协议版本、能力列表和连接状态 |
| `browser.getSnapshot` | `tabId`、`options` | 页面信息、元素、版本和截断状态 |
| `browser.getAccessibilityTree` | `tabId`、可选深度和节点上限 | 可访问性结构及版本 |
| `browser.getActiveTab` | 可选窗口范围 | 当前可访问的活动标签页 |
| `browser.getTabs` | 可选过滤条件 | Agent 有权查看的标签页列表 |
| `browser.createTab` | `url`、可选 `active` | 新标签页及初始状态 |
| `browser.closeTab` | `tabId` | 关闭结果 |
| `browser.switchTab` | `tabId` | 切换后的活动标签页 |
| `browser.batch` | `operationId`、`actions`、`stopOnError` | 逐项结果和汇总状态 |
| `browser.getOperation` | `operationId` | 当前 Agent 的操作状态、最终结果或标准错误；不会触发执行 |
| `browser.getEvents` | `cursor`、`limit` | 当前会话内的有序事件、下一游标和重新同步标记 |

### 5.2 Page 方法

| 方法 | 关键参数 | 成功结果 |
|---|---|---|
| `page.goto` | `tabId`、`url`、可选等待条件 | 导航结果和最终页面信息 |
| `page.back` | `tabId` | 导航结果 |
| `page.forward` | `tabId` | 导航结果 |
| `page.reload` | `tabId` | 刷新结果和新页面版本 |
| `page.getUrl` | `tabId` | 当前地址和页面版本 |
| `page.getTitle` | `tabId` | 当前标题和页面版本 |
| `page.getText` | `tabId`、可选范围与长度上限 | 可见文本和截断状态 |
| `page.waitForNavigation` | `tabId`、超时 | 导航完成或超时错误 |
| `page.waitForSelector` | `tabId`、定位条件、状态、超时 | 目标元素及页面版本 |
| `page.waitForText` | `tabId`、文本、超时 | 匹配状态和页面版本 |
| `page.subscribe` | `tabId`、事件类型、过滤条件 | `subscriptionId` 和初始事件游标 |
| `page.unsubscribe` | `subscriptionId` | 取消结果 |
| `page.getChanges` | `tabId`、`sinceVersion` | 页面增量变化或完整同步标记；事件恢复使用 `browser.getEvents` |

### 5.3 Locator 方法

| 方法 | 关键参数 | 成功核验重点 |
|---|---|---|
| `locator.find` | `tabId`、`locator` | 返回匹配列表和歧义标记，不执行操作 |
| `locator.click` | `tabId`、`locator` | 点击后页面或元素状态 |
| `locator.fill` | `tabId`、`locator`、`value` | 元素最终值及必要事件状态 |
| `locator.type` | `tabId`、`locator`、`text`、可选按键间隔 | 最终输入状态 |
| `locator.clear` | `tabId`、`locator` | 元素已清空 |
| `locator.press` | `tabId`、`locator`、`key` | 按键行为及必要页面变化 |
| `locator.hover` | `tabId`、`locator` | 悬停目标有效 |
| `locator.check` | `tabId`、`locator` | 最终选中状态 |
| `locator.uncheck` | `tabId`、`locator` | 最终未选中状态 |
| `locator.selectOption` | `tabId`、`locator`、选项值或标签 | 最终选项状态 |
| `locator.scrollIntoView` | `tabId`、`locator` | 元素进入可操作视区 |

填写和输入接口不用于读取或写入密码字段。涉及敏感或高风险提交时，仍需经过风险分类。

## 6. 批量操作

### 6.1 请求示例

```json
{
  "jsonrpc": "2.0",
  "id": "req_batch_001",
  "method": "browser.batch",
  "params": {
    "sessionId": "ses_123",
    "tabId": 123,
    "operationId": "op_batch_001",
    "stopOnError": true,
    "actions": [
      {
        "type": "fill",
        "locator": { "ref": "el_001" },
        "value": "example"
      },
      {
        "type": "click",
        "locator": { "ref": "el_002" }
      }
    ]
  }
}
```

### 6.2 执行语义

- `actions` 默认按数组顺序执行。
- `stopOnError` 默认值为 `true`。
- 每项结果必须包含 `index`、`status`；成功时包含操作结果，失败时包含标准错误。
- 遇错停止时，后续项状态为 `skipped`，不能省略。
- 批次开始前对当前可定位动作执行风险预扫描；已能识别的高风险动作导致整个批次在执行前被拒绝，并提示单独提交。
- 每个动作开始前必须重新定位并重新分类风险。若前序动作使后续动作变为高风险，系统在该动作执行前停止：当前项为 `blocked` 并携带 `CONFIRMATION_REQUIRED`，错误 `data.requiresSeparateSubmission` 为 `true`，后续项为 `skipped`；此错误不在批次内创建用户确认，Agent 必须获取新快照后单独提交该动作，不得等待本批次的用户确认事件。
- 动态高风险停止时，已执行项保留实际结果；若已有动作完成，批次汇总为 `partial`，否则为 `failed`。
- 同一文档的无关变化不自动使后续引用失效；每个引用执行前复核身份，失效时当前项返回 `STALE_ELEMENT_REFERENCE`。
- 批量不具备跨操作事务保证，结果需包含 `transactional: false`。
- 批次汇总状态为 `completed`、`partial` 或 `failed`。

## 7. 权限校验

### 7.1 校验顺序

每个请求按以下顺序校验：协议版本与请求外层结构 → Agent 身份和会话 → 方法能力 → 参数结构 → 标签页范围与页面支持状态 → 预定位与操作风险 → 人工确认 → 执行前复核。该顺序与系统架构的单条指令管线一致。

### 7.2 权限维度

| 维度 | 示例 |
|---|---|
| Agent 能力 | 是否允许读取、操作、管理标签页或订阅事件 |
| 标签页范围 | 仅当前标签页、明确分配的标签页或用户授权范围 |
| 页面范围 | 普通站点、敏感站点、不支持的浏览器页面 |
| 方法范围 | 只读、普通写入、受限写入 |
| 风险等级 | 普通、受限、高风险 |
| 资源限额 | 请求速率、批量长度、快照大小、订阅数量 |

最小授权是默认策略；一个 Agent 获得读取权限不代表获得写入或关闭标签页权限。

### 7.3 高风险确认流程

1. Agent 提交操作并携带唯一 `operationId`。
2. 系统识别高风险，返回 `CONFIRMATION_REQUIRED`，其中包含 `confirmationId` 和过期时间。
3. 浏览器侧向用户展示站点、动作、目标及不可逆风险；Agent 收到确认等待事件，也可通过 `browser.getOperation` 查询 `waiting_confirmation` 状态。
4. 用户确认或拒绝后，系统生成 `operation.confirmationResolved` 事件；系统不会在确认后自动执行。确认后操作状态为 `confirmed_pending_retry`，拒绝后为 `failed`。
5. 若已确认，Agent 使用相同 `operationId`、相同参数和 `confirmationId` 重新提交；若已拒绝，重新提交返回 `CONFIRMATION_DENIED`。
6. 系统核对操作指纹、页面文档、目标元素、会话和确认有效期，全部有效才执行；无关 DOM 变化不自动使确认失效，但必须重新核验目标和权限。

确认编号不是授权凭据，不能跨 Agent、会话、页面文档、目标或操作复用。Agent 没有“批准确认”的接口。目标变化、页面文档变化、确认过期或参数不一致时返回 `STALE_CONFIRMATION`。断连会终止原会话和确认，重连后须在新会话重新发起高风险操作。

## 8. 错误处理

### 8.1 标准错误格式

```json
{
  "jsonrpc": "2.0",
  "id": "req_002",
  "error": {
    "code": -32001,
    "message": "Element not found",
    "data": {
      "errorType": "ELEMENT_NOT_FOUND",
      "retryable": false,
      "operationId": "op_002",
      "snapshotVersion": "sv_42",
      "details": {
        "strategy": "ref"
      }
    }
  }
}
```

`message` 用于统一诊断，`errorType` 供程序处理。`details` 不得包含输入值、页面敏感内容或认证信息。

### 8.2 错误码

| 错误码 | `errorType` | 含义 | 建议处理 |
|---|---|---|---|
| -32700 | `PARSE_ERROR` | 报文无法解析 | 修正报文 |
| -32600 | `INVALID_REQUEST` | 请求结构无效 | 修正请求 |
| -32601 | `METHOD_NOT_FOUND` | 方法不存在或未开放 | 检查版本与能力 |
| -32602 | `INVALID_PARAMS` | 参数无效 | 按字段提示修正 |
| -32603 | `INTERNAL_ERROR` | 未分类内部错误 | 记录诊断并上报 |
| -32001 | `ELEMENT_NOT_FOUND` | 未找到元素 | 更新快照或调整定位 |
| -32002 | `STALE_ELEMENT_REFERENCE` | 引用已失效 | 重新定位，禁止沿用旧引用 |
| -32003 | `OPERATION_TIMEOUT` | 等待或执行超时 | 查询状态后再决定，不盲目重试 |
| -32004 | `NAVIGATION_INTERRUPTED` | 操作被导航中断 | 获取新页面状态 |
| -32005 | `UNSUPPORTED_PAGE` | 页面不受支持 | 停止该路径或请求用户处理 |
| -32006 | `PERMISSION_DENIED` | 身份、能力或范围不足 | 请求用户授权，不得绕过 |
| -32007 | `SESSION_EXPIRED` | 会话无效或过期 | 重新认证并同步状态 |
| -32008 | `CONFIRMATION_REQUIRED` | 需要用户确认 | 单操作等待用户决定；若 `requiresSeparateSubmission: true`，获取新快照并单独提交 |
| -32009 | `CONFIRMATION_DENIED` | 用户拒绝 | 不执行操作 |
| -32010 | `RATE_LIMITED` | 超出资源或速率限制 | 降低请求频率 |
| -32011 | `INVALID_ELEMENT_STATE` | 元素不可见、禁用或状态不符 | 更新状态或调整操作 |
| -32012 | `BRIDGE_UNAVAILABLE` | 插件或通信层不可用 | 恢复连接后重新同步 |
| -32013 | `AMBIGUOUS_LOCATOR` | 定位匹配多个目标 | 增加语义约束 |
| -32014 | `STALE_CONFIRMATION` | 确认过期或操作指纹变化 | 重新发起确认 |
| -32015 | `OPERATION_OUTCOME_UNKNOWN` | 已执行但结果无法确认 | 查询页面，不自动重放 |
| -32016 | `DUPLICATE_OPERATION` | 相同操作正在处理 | 使用 `browser.getOperation` 查询 |
| -32017 | `OPERATION_ID_CONFLICT` | 相同操作标识对应不同参数 | 更换标识并核对原操作状态 |
| -32018 | `VERIFICATION_FAILED` | 操作后未达到可核验目标状态 | 获取新快照并诊断 |
| -32019 | `TAB_NOT_FOUND` | 标签页不存在或已关闭 | 重新枚举标签页，不切换目标 |
| -32020 | `UNSUPPORTED_PROTOCOL_VERSION` | 协议主版本不兼容 | 协商支持版本 |

### 8.3 重试规则

- 读取、查找等幂等请求可在连接恢复后重试。
- 点击、提交、删除、发送等非幂等操作不得仅因超时自动重试。
- 写操作超时、断连或重连后，先调用 `browser.getOperation` 查询原 `operationId`，再读取页面状态；不得直接重放。
- 携带相同 `operationId` 的重发只用于获取去重结果，或完成已获用户确认的原高风险操作。
- 返回 `OPERATION_OUTCOME_UNKNOWN` 时，Agent 必须先读取页面状态，且不得自动重试。

## 9. 回调与异步事件

### 9.1 通知格式

双向连接使用 JSON-RPC 通知；只支持请求—响应的接入方式通过 `browser.getEvents` 获取相同事件。

```json
{
  "jsonrpc": "2.0",
  "method": "page.changed",
  "params": {
    "eventId": "evt_1001",
    "sequence": 18,
    "sessionId": "ses_123",
    "subscriptionId": "sub_001",
    "tabId": 123,
    "occurredAt": "2026-11-19T19:33:39+08:00",
    "data": {
      "snapshotVersion": "sv_43",
      "changeTypes": ["elements-added", "text-changed"]
    }
  }
}
```

### 9.2 事件类型

| 事件 | 触发时机 |
|---|---|
| `page.changed` | 订阅范围内出现有效 DOM 或文本变化 |
| `page.navigationStarted` | 页面开始导航 |
| `page.navigationCompleted` | 导航完成并产生新页面版本 |
| `browser.tabUpdated` | 已授权标签页状态变化 |
| `operation.confirmationRequired` | 高风险操作等待用户确认 |
| `operation.confirmationResolved` | 用户已确认或拒绝 |
| `session.closed` | 会话被主动关闭、撤销或过期且连接仍可用时尽力发送；断连本身不保证送达 |

### 9.3 事件可靠性

- 每个会话使用统一、单调递增的 `sequence`，覆盖该会话的页面、标签页、确认和会话事件；`subscriptionId` 只表示投递过滤条件，不单独维护序号。
- `browser.getEvents` 的 `cursor` 是不透明且仅属于当前会话的游标，不能跨会话使用；响应包含 `events`、`nextCursor` 和 `resyncRequired`。
- Agent 发现序号缺口或服务返回 `resyncRequired: true` 时，页面状态通过 `page.getChanges` 或完整快照恢复，写操作状态通过 `browser.getOperation` 恢复。
- 当前会话的事件只保留在有限窗口内；确认事件丢失时可查询操作状态，不能保证非页面事件无限期重放。
- Agent 断连即终止原会话、订阅和游标。重新认证后必须建立新会话、重新订阅并完整同步，不得沿用旧游标。
- 事件只包含必要变化摘要，详细内容按需读取。
- 事件不得发送给未订阅或无标签页权限的 Agent。

## 10. 版本、兼容性与限流

- 主版本不兼容时才升级；新增可选字段和新方法可在兼容版本中增加。
- `browser.getInfo` 必须返回支持的方法和能力。
- 已废弃字段应有替代字段和移除计划，不得无提示改变语义。
- 系统可限制单连接并发、批量动作数、事件订阅数、文本长度和快照元素数。
- 达到限制时返回明确错误或截断标记，不得静默丢弃。

## 11. 接口验收检查表

- 两种以上接入形态对同一方法得到相同业务语义。
- 所有响应均关联原请求，所有错误均可按 `errorType` 处理。
- 多匹配、元素失效、导航中断和状态未知均有独立错误。
- 高风险确认不能跨会话或修改参数后复用。
- 非幂等请求不会因超时或重连被自动重复执行。
- 事件具有顺序、权限过滤和缺口恢复机制。
- 快照、文本、事件和日志均不包含密码、Cookie 或认证令牌。
