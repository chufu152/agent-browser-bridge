# Universal Browser Agent（UBA）项目里程碑

| 文档属性 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 文档日期 | 2026-11-19 |
| 规划范围 | 从需求冻结到高级能力的阶段交付 |
| 排期原则 | 以验收门槛和依赖关系驱动，不在规划阶段承诺未经验证的工期 |

## 1. 阶段总览

| 阶段 | 名称 | 核心目标 | 前置依赖 | 退出条件 |
|---|---|---|---|---|
| M0 | 需求与协议基线 | 冻结范围、术语、风险和验收口径 | 项目目标明确 | 五份规划文档评审通过 |
| M1 | 浏览器控制核心 | 无截图完成页面读取与常见操作 | M0 | 核心功能与插件恢复测试通过 |
| M2 | 本地通信系统 | 独立本地 Agent 控制真实浏览器 | M1 | 认证、路由、会话和异常恢复通过 |
| M3 | 通用 Agent 接入 | 多类 Agent 共用同一协议 | M2 | 两个独立 Agent 完成同一任务 |
| M4 | 性能与规模优化 | 降低重复解析和无效调用 | M1–M3 基线数据 | 性能门槛通过且无安全回归 |
| M5 | 高级能力 | 扩展复杂页面、监控和治理能力 | M1–M4 稳定 | 高级场景与发布审查通过 |

每个阶段必须同时交付功能、测试证据、接口或架构更新以及已知限制，不能仅以“代码完成”作为完成标准。

## 2. M0：需求与协议基线

### 2.1 目标

- 明确直接 DOM 操作是默认执行路径。
- 统一 Agent、接入层、通信治理层、插件控制层和页面执行层的职责。
- 冻结首版方法、通用结果、错误码、权限分级和高风险确认流程。
- 建立标准测试页面、性能指标和多 Agent 验收任务。

### 2.2 交付物

1. 项目概述、系统架构、接口、里程碑和测试五份基线文档。
2. 首版能力清单与非目标清单。
3. 普通、受限和高风险操作的初始分类表。
4. 标准测试页面需求及功能—接口—测试追踪关系，具体映射记录在测试文档第 12 节。
5. 可重复性能基准：标准页面规模、简单操作集合、预热和样本规则。
6. 首版兼容范围：当前桌面浏览器的当前稳定版及前一稳定版，以及项目当前桌面系统；其他平台不属于首版兼容承诺，执行时记录实际产品和版本。
7. 待决策项清单：复杂框架范围、文件传输范围、敏感站点策略和视觉补充是否立项。

### 2.3 依赖关系

- 依赖用户提供的项目技术目标和核心约束。
- 不依赖任何具体实现框架。

### 2.4 验收标准

- 五份文档对同一会话、引用、权限和错误语义无冲突。
- 所有首版方法均能映射到架构组件和测试场景。
- 明确禁止截图识别作为常规执行路径。
- 明确 Agent 无法自行批准高风险操作。
- 未决事项不阻塞 M1 核心范围。

## 3. M1：浏览器控制核心

### 3.1 目标

在插件内部完成最小可用闭环：标签页识别、页面快照、元素定位、真实交互、页面等待和基础变化观察，不依赖外部 Agent 或截图。

### 3.2 主要工作

- 建立插件控制层和页面执行层的受控消息边界。
- 实现标准交互元素提取、可见性和可用性判断。
- 实现快照版本、短期元素引用和失效检测。
- 实现引用及语义定位，保留结构和路径定位。
- 实现点击、填写、输入、清空、按键、悬停、勾选、选项选择和滚动。
- 实现跳转、后退、前进、刷新、页面信息读取和状态等待。
- 实现基础标签页枚举、创建、切换和关闭。
- 建立基础审计、诊断信息和不受支持页面处理。

### 3.3 交付物

- 可本地加载的插件核心工程。
- 面向标准测试页面的核心功能测试集。
- 插件内部命令与页面结果映射说明。
- 已知不支持页面和组件清单。
- 初始执行耗时基线。

### 3.4 依赖关系

- 依赖 M0 的方法、定位、结果和错误语义。
- 不依赖 M2 的外部通信；可通过受控测试驱动调用内部命令。
- 高风险最终提交可暂缓支持，但识别和阻断规则必须先建立。

### 3.5 验收标准

- 在标准页面上完成读取、定位、点击、输入、选择、滚动和导航全链路。
- 所有核心用例不依赖截图识别、坐标预测或模拟鼠标坐标。
- 操作后核验真实状态，失败不返回伪成功。
- 多匹配返回歧义错误；旧引用不会操作到替换后的其他元素。
- 页面导航和插件后台恢复后，旧页面上下文不会误用。
- 特殊页面返回明确的不支持错误。
- 核心功能测试全部通过，安全阻断用例全部通过。

## 4. M2：本地通信系统

### 4.1 目标

建立本地通信与治理能力，使独立本地程序通过统一协议控制用户真实浏览器。

### 4.2 主要工作

- 建立本地连接、插件与本地服务间的受控通信。
- 实现 Agent 身份、独立凭据、认证、撤销和会话过期。
- 实现请求路由、请求响应关联、超时和并发管理。
- 实现方法权限、标签页授权和基础资源限额。
- 实现断连、插件后台恢复、本地服务重启和请求去重策略。
- 建立审计记录和诊断入口，确保敏感字段不进入普通日志。

### 4.3 交付物

- 本地通信服务和插件连接能力。
- BCP 请求、响应和错误处理能力。
- 本地连接配置及 Agent 登记、撤销流程。
- 会话与标签页授权管理界面或等效用户入口。
- 通信异常和恢复测试报告。

### 4.4 依赖关系

- 依赖 M1 的插件内部命令和状态恢复能力。
- 依赖 M0 的认证、会话、权限和错误模型。
- 为 M3 的工具适配器和 SDK 提供唯一调用入口。

### 4.5 验收标准

- 独立本地程序可通过认证后获取快照并完成一次真实页面操作。
- 未认证、错误凭据、撤销凭据、过期会话和越权标签页请求全部被拒绝。
- 非本机或未经允许的来源无法建立控制连接。
- 本地服务或插件后台重启后，系统能重建连接和必要状态；原会话与订阅失效并重新认证。
- 同一 Agent 可在默认 15 分钟去重窗口内通过 `browser.getOperation` 跨重启查询操作结果；相同标识对应不同参数时被拒绝。
- 已开始且结果未知的非幂等操作不会在恢复后自动重放。
- 所有请求可追踪到 Agent、会话、标签页和结果，日志无敏感值。

## 5. M3：通用 Agent 接入

### 5.1 目标

让至少两个独立实现的 Agent 在不修改浏览器控制引擎的情况下，通过同一 BCP 完成相同任务。

### 5.2 主要工作

- 提供标准工具适配层，将浏览器能力暴露为可发现工具。
- 提供两类 SDK 接口，封装认证、请求、错误、事件和重连。
- 实现多 Agent 会话、标签页、事件和资源隔离。
- 实现页面订阅、取消订阅、事件推送或事件查询。
- 实现完整的高风险用户确认闭环。
- 提供示例 Agent 任务和统一接入指南。

### 5.3 交付物

- 标准工具适配层。
- 两类 SDK 及示例。
- 多 Agent 会话与权限管理。
- 异步事件和人工确认机制。
- 两个独立 Agent 的互操作测试报告。

### 5.4 依赖关系

- 依赖 M2 的稳定本地协议和认证。
- 依赖 M1 的快照、定位、操作和观察能力。
- 不引入特定模型依赖，示例 Agent 只用于验证协议。

### 5.5 验收标准

- 两个独立 Agent 使用同一任务定义和同一 BCP 方法完成浏览器任务。
- 新增 Agent 不需要修改快照、定位或操作组件。
- Agent 之间无法读取对方未授权标签页、事件和确认编号。
- 高风险操作未经用户确认时执行成功数为零。
- 用户确认后修改操作参数或目标时，旧确认失效。
- 事件序号缺口能够被检测并触发重新同步。

## 6. M4：性能与规模优化

### 6.1 目标

在不改变协议语义、不降低安全标准的前提下，降低快照、操作和事件处理开销。

### 6.2 主要工作

- 引入基于页面版本的快照缓存和缓存失效策略。
- 优化元素引用复用与失效后的重新定位。
- 实现有序批量执行、逐项结果和遇错策略。
- 实现 DOM 增量变化、事件合并和变化查询。
- 完善导航、元素和页面状态的智能等待。
- 建立标准数据集、重复性能基准和回归报告。

### 6.3 交付物

- 快照缓存、引用复用、增量更新和批量操作能力。
- 智能等待和异步通知优化。
- 性能基准数据、对比报告和容量限制说明。
- 优化后的安全与一致性回归报告。

### 6.4 依赖关系

- 依赖 M1–M3 的功能基线和稳定测试集。
- 依赖 M2/M3 的请求追踪与多 Agent 隔离数据。
- 性能目标以受控标准页面和本地环境为准，页面业务耗时单列。

### 6.5 验收标准

- 标准页面完整快照第 95 百分位耗时不超过 1 秒。
- 本地简单页面操作的插件执行耗时第 95 百分位不超过 300 毫秒。
- 无有效变化时快照缓存可命中，且不会返回过期页面状态。
- 增量事件不会漏报导致 Agent 长期使用旧状态；序号缺口可恢复。
- 批量执行逐项状态完整，默认遇错停止，后续项明确标记跳过。
- 优化前后的权限、高风险确认和敏感信息过滤测试全部通过。

## 7. M5：高级能力与发布准备

### 7.1 目标

在稳定核心上支持复杂页面、页面监控、文件相关能力和更完整的用户治理。

### 7.2 主要工作

- 分阶段支持阴影 DOM、同源及可授权的跨域框架。
- 建立框架与页面上下文的独立管理。
- 评估并实现文件上传下载的显式授权。
- 支持复杂自定义组件和必要的用户介入流程。
- 完善页面监控、操作审计、权限管理和日志清理。
- 完成兼容性、安全、恢复、性能和发布审查。

### 7.3 交付物

- 复杂页面与框架支持能力及明确限制。
- 文件传输等受限能力的用户授权流程。
- 完整权限与审计管理界面。
- 全量测试报告、用户操作说明和已知问题清单。
- 发布候选版本及回滚方案。

### 7.4 依赖关系

- 依赖 M1–M4 全部安全和性能回归通过。
- 文件能力依赖独立的权限评审。
- 视觉补充能力若被提议，必须另行立项，不得改变默认 DOM 路径。

### 7.5 验收标准

- 支持的阴影 DOM 和框架用例通过；不支持时明确返回限制。
- 文件上传下载未经显式授权不能执行。
- 所有高级能力沿用统一权限、审计和错误模型。
- 全量测试无阻断级或严重级未解决缺陷。
- 发布、升级、卸载、重装和回滚行为均有验证记录。

## 8. 跨阶段依赖与并行规则

```text
M0 需求与协议基线
 └─ M1 浏览器控制核心
     └─ M2 本地通信系统
         └─ M3 通用 Agent 接入
             └─ M4 性能与规模优化
                 └─ M5 高级能力与发布准备
```

- M0 的测试页面准备可与文档评审并行。
- M1 的测试驱动与核心组件可并行，但接口语义不得各自演化。
- M2 的用户授权入口可与通信路由并行。
- M3 的两类 SDK 可并行，但必须使用同一协议测试集。
- M4 只能在已有可靠基线后优化，不得通过跳过安全检查获得性能。
- M5 的每项高级能力都可独立验收，但不能绕过统一治理层。

## 9. 阶段质量门禁

每个阶段退出前必须满足：

1. 功能验收用例全部执行并留存结果。
2. 无未解决的阻断级和严重级缺陷。
3. 接口、架构和测试文档已同步到实际行为。
4. 安全负向用例通过，未发生权限绕过或敏感信息泄露。
5. 已知限制、不支持页面和恢复方式有明确记录。
6. 下一阶段所需接口和依赖已稳定，或变更已评审。

## 10. 变更控制

以下变更必须同时更新五份文档的相关部分并重新评审：

- 将截图或视觉识别引入常规执行路径。
- 开放远程访问或扩大标签页、站点和方法权限。
- 修改高风险确认、非幂等重试或会话隔离语义。
- 新增文件、支付、发布、删除或账户安全相关能力。
- 修改已发布方法的参数、结果或错误语义。
- 性能优化导致缓存、事件顺序或状态核验变化。

## 11. 里程碑发布与推送规则

- 每个里程碑只有完成对应交付物、测试验证和质量门禁后，才允许推送到公共仓库的 `main` 分支。
- 每次推送必须对应一个明确的里程碑或已评审的里程碑修订，提交说明需包含阶段编号、交付范围和验证结论。
- 未完成验证的实现、临时文件、本机状态、密钥和 `.workbuddy` 目录不得推送到公共仓库。
- 当前五份规划文档及 `.gitignore` 作为 M0“需求与协议基线”的已验证交付物推送；后续 M1–M5 按相同规则推送。
- 若推送后发现阻断问题，不以历史改写掩盖，应通过新的修复提交恢复，并在对应阶段记录原因和复验结果。

## 12. 里程碑完成定义

一个里程碑只有同时满足“交付物齐全、依赖已满足、验收证据充分、文档一致、安全门槛通过”五项条件才视为完成。部分功能可用但缺少恢复、权限或测试证据时，阶段保持进行中。完成并通过验证后，按本章规则推送到 `main` 分支。
