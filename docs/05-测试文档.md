# Universal Browser Agent（UBA）测试文档

| 文档属性 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 文档日期 | 2026-11-19 |
| 测试范围 | 功能、兼容性、性能、安全、异常恢复和多 Agent 隔离 |
| 核心约束 | 常规功能测试不得依赖 Agent 后台截图识别或坐标预测 |
| 当前状态 | 测试规划基线，尚未执行实现测试 |

## 1. 测试目标

1. 验证结构化页面读取和直接页面操作能完成核心浏览器任务。
2. 验证不同 Agent 和接入方式具有一致协议行为。
3. 验证权限、敏感信息和高风险确认无法被绕过。
4. 验证页面变化、连接中断和后台恢复时不会误操作或重复执行。
5. 建立可重复的性能基线和跨版本兼容性证据。

## 2. 测试策略

### 2.1 测试层级

| 层级 | 重点 | 典型证据 |
|---|---|---|
| 组件测试 | 元素提取、定位、风险分类、参数校验和状态判断 | 输入、预期输出、错误类型 |
| 插件集成测试 | 插件控制层与真实页面之间的完整闭环 | 页面前后状态、操作结果 |
| 协议集成测试 | 认证、会话、路由、错误、事件和去重 | 请求响应记录、审计记录 |
| 端到端测试 | Agent 从任务规划到浏览器完成操作 | 任务轨迹、最终页面状态 |
| 非功能测试 | 兼容性、性能、安全、恢复和资源隔离 | 基准报告、安全报告、恢复报告 |

### 2.2 测试原则

- 使用受控标准页面作为核心验收依据，第三方网站仅作为兼容性补充。
- 截图和视频只允许作为测试取证，不作为功能成功的主要判定依据。
- 功能断言必须检查真实页面状态，而非只检查接口返回。
- 每个正向能力至少配置一个权限、状态或异常负向用例。
- 性能优化后必须重新执行安全和一致性回归。
- 测试数据不包含真实用户密码、Cookie、令牌或私人数据。

## 3. 测试环境与标准页面

### 3.1 环境矩阵

| 维度 | 覆盖要求 |
|---|---|
| 浏览器版本 | 目标浏览器当前稳定版及前一稳定版 |
| 操作系统 | 项目声明支持的桌面系统分别验证 |
| 页面缩放 | 默认、放大和缩小场景 |
| 语言与文本 | 中文、英文、长文本和特殊字符 |
| 页面类型 | 静态、动态更新、单页导航、多标签页 |
| 网络状态 | 正常、慢响应、请求失败、离线后恢复 |
| 插件状态 | 首次加载、后台休眠恢复、升级、卸载与重装 |
| Agent 状态 | 单 Agent、多 Agent、断连、重连和凭据撤销 |

具体版本号在测试执行时记录，不在规划阶段固定。

### 3.2 标准测试页面

至少准备以下可重复页面：

1. **基础控件页**：按钮、链接、文本框、多行输入、选择框、单选、复选和表单。
2. **语义页**：可访问名称、关联标签、输入提示、禁用和隐藏元素。
3. **动态页**：延迟插入、删除、文本变化、属性变化和高频变化。
4. **导航页**：普通跳转、前进后退、刷新和单页导航。
5. **歧义页**：多个相同名称按钮和重复文本。
6. **敏感页**：密码框、模拟账户安全入口和模拟敏感文本，不使用真实凭据。
7. **高风险页**：模拟支付、删除、发送、发布和最终提交按钮，不连接真实业务。
8. **复杂页**：阴影 DOM、框架、画布及自定义组件，用于分阶段验收和限制验证。
9. **规模页**：大量元素、长文本和持续变化，用于性能与限流测试。

### 3.3 可重复性能基准

首版性能验收统一使用以下基线，避免用不同页面规模比较耗时：

| 项目 | 基线定义 |
|---|---|
| 标准页面 | 本地静态加载完成；不超过 3000 个 DOM 节点、200 个交互元素、12 层 DOM 深度和 20000 个可见文本字符；无框架和阴影 DOM |
| 完整快照 | 冷缓存读取标准页面，包含交互元素，不包含完整页面文本 |
| 简单操作集合 | 对可见且可用的已定位元素执行点击、填写、清空、勾选、取消勾选、选项选择和滚动；不触发导航或外部业务请求 |
| 缓存快照 | 页面版本未变化时的重复读取 |
| 预热与样本 | 先预热 10 轮，再执行至少 100 轮；报告中位数、P95、最大值和样本数 |
| 支持环境 | 首版覆盖当前桌面浏览器的当前稳定版及前一稳定版，以及项目当前桌面系统；执行时记录实际产品和版本。其他平台不属于首版兼容承诺，不以单一环境推断全部兼容 |

若标准页面或操作集合发生变化，必须建立新基线，不得与旧数据直接比较。

## 6. 兼容性测试

### 6.1 浏览器与页面兼容

- 在环境矩阵中重复核心功能测试，不因浏览器视觉差异改变定位结果。
- 验证普通导航和单页导航后的快照、引用与订阅状态。
- 验证不同页面缩放和语言下仍能使用语义定位。
- 验证动态组件异步挂载、卸载和状态切换。
- 验证阴影 DOM 和框架在当前阶段声明的支持范围。
- 对画布和非 DOM 交互验证“明确限制”，不要求以截图点击兜底。

## 7. 性能测试

### 7.1 指标定义

| 指标 | 测量起点与终点 | 验收目标 |
|---|---|---|
| 完整快照耗时 | 接收有效请求至快照生成完成 | 标准页面 P95 不超过 1 秒 |
| 简单操作插件耗时 | 开始定位至操作后状态核验完成 | 本地标准页面 P95 不超过 300 毫秒 |
| 缓存快照耗时 | 缓存命中判断至响应生成 | 建立基线并持续回归，不得返回过期状态 |
| 增量更新延迟 | 页面有效变化至事件可查询或推送 | 建立基线，事件顺序和完整性优先 |
| 批量处理开销 | 批次开始至逐项结果齐全 | 与等效逐条请求对比并记录收益 |
| 恢复耗时 | 连接或后台恢复至可接受新请求 | 建立基线，无重复非幂等执行 |

P95 表示第 95 百分位。页面业务响应、外部网络和 Agent 模型推理耗时必须与插件执行耗时分开记录。

### 7.2 测试方法

1. 固定标准页面、数据规模、浏览器状态和本地测试环境。
2. 先预热，再重复足够轮次，报告中位数、P95、最大值和样本数。
3. 分别测量无缓存、有缓存、增量、批量和高频变化场景。
4. 在单 Agent 和多 Agent 负载下分别测量，并记录资源使用。
5. 保存版本、环境、页面版本和原始结果，确保可重复比较。

### 7.3 性能退化与边界场景

- 超大页面达到元素或文本上限时必须截断并标记。
- 高频 DOM 变化不得导致事件队列无限增长。
- 缓存失效频繁时允许降级到完整解析，但不得跳过权限检查。
- 长任务不得使其他 Agent 的认证、读取或取消操作永久饥饿。
- 达到速率和并发限制时返回 `RATE_LIMITED` 或明确错误。

### 8.3 数据保护与审计

- 检查快照、文本、事件、错误和日志中的密码、Cookie、令牌及完整敏感输入。
- 验证敏感字段的拒绝策略不能通过更换定位方式绕过。
- 验证审计包含必要追踪字段，但不包含认证材料和页面全文。
- 验证日志保留期限、用户清理和访问权限。
- 验证卸载、重装和凭据更新后的授权行为符合产品说明。

安全验收要求：未授权执行成功数为零，高风险未确认执行成功数为零，敏感凭据泄露数为零。

## 9. 异常处理与恢复测试

| 用例 ID | 异常场景 | 预期结果 |

| E-REQ-003 | 重复操作标识且原请求处理中 | 返回 `DUPLICATE_OPERATION` 或原结果，不重复执行 |
| E-REQ-004 | 相同操作标识携带不同参数 | 返回 `OPERATION_ID_CONFLICT`，不执行新参数 |
| E-REQ-005 | 查询处理中、待确认、已确认待重提、完成、失败和未知操作 | `browser.getOperation` 返回 `processing`、`waiting_confirmation`、`confirmed_pending_retry`、`completed`、`failed` 或 `unknown`，不触发执行 |
| E-REQ-006 | 本地服务与插件重启后查询去重窗口内操作 | 原操作结果仍可查询，不重复执行 |
| E-PAGE-001 | 操作中发生导航 | 返回导航中断或新状态，不误操作 |
| E-PAGE-002 | 元素在定位后删除或替换 | 旧引用失效，目标不转移 |
| E-PAGE-003 | 标签页在操作中关闭 | 明确失败并清理上下文 |
| E-NET-001 | 页面加载慢或失败 | 按等待条件超时，保留诊断状态 |
| E-CON-001 | Agent 在操作前断连 | 尚未开始的安全操作可取消 |
| E-CON-002 | Agent 在操作后断连 | 短期保留结果，同一 Agent 新会话通过 `browser.getOperation` 查询 |
| E-CON-003 | 操作结果未知后重连 | 返回状态未知，禁止自动重放 |
| E-SYS-001 | 插件后台休眠恢复 | 重建页面状态，旧引用和确认失效 |
| E-SYS-002 | 本地通信服务重启 | 原会话、订阅和事件游标失效；重新认证并完整同步，操作结果仍可查询 |
| E-SYS-003 | 插件与本地服务消息乱序或重复 | 请求关联正确，不重复执行 |
| E-SYS-004 | 事件缓存溢出 | 标记同步缺口，不假装事件完整 |

## 10. 阶段测试范围

| 里程碑 | 必测范围 | 退出门禁 |
|---|---|---|
| M0 | 文档一致性、用例可执行性、标准页面覆盖 | 需求—接口—测试可追踪 |
| M1 | 快照、定位、操作、页面、标签页、基础恢复 | 核心功能和安全阻断全部通过 |
| M2 | 认证、路由、会话、权限、断连和重启 | 本地独立程序端到端通过 |
| M3 | 多 Agent、SDK/工具适配、事件和人工确认 | 两个 Agent 互操作及隔离通过 |
| M4 | 缓存、引用复用、增量、批量和性能 | 性能达标且安全回归通过 |
| M5 | 复杂页面、文件权限、全量兼容与发布恢复 | 全量门禁和发布审查通过 |

## 11. 缺陷分级与验收门禁

### 11.1 缺陷分级

| 级别 | 示例 | 阶段退出要求 |
|---|---|---|
| 阻断 | 未授权控制、高风险绕过、真实凭据泄露、错误页面破坏性操作 | 必须修复并回归 |
| 严重 | 核心操作不可用、非幂等重复执行、多 Agent 数据串用 | 必须修复并回归 |
| 一般 | 单一边界功能失败、可恢复的状态错误、明确性能退化 | 原则上修复；延期需评审 |
| 轻微 | 文档、诊断展示和不影响结果的表现问题 | 记录并排期 |

### 11.2 测试进入条件

- 被测版本、接口版本和测试环境可识别。
- 标准测试页面可用，测试数据无真实敏感信息。
- 功能具有可观察的真实状态断言。
- 高风险测试使用模拟业务页面，不连接真实支付或发布系统。

### 11.3 测试退出条件

- 当前阶段必测用例全部执行，核心用例全部通过。
- 无阻断级和严重级未解决缺陷。
- 安全负向用例和异常恢复用例全部通过。
- 性能报告包含环境、样本、分位值和原始结果。
- 失败、限制和延期项均有记录、责任归属和复测条件。
- 实际行为与架构、接口和里程碑文档一致。

### 12.2 阶段测试报告

阶段测试报告至少包含：

1. 版本、环境和执行范围。
2. 通过率及按功能、兼容、性能、安全和恢复分类的结果。
3. 未解决缺陷及风险说明。
4. 性能基线和与上一版本的对比。
5. 未覆盖页面和明确限制。
6. 是否满足阶段退出门禁的结论。

测试完成不以“接口均返回成功”为准，而以真实页面状态、安全边界和恢复行为均得到验证为准。
