# M4 性能基准说明

## 核心优化：ref 生成 O(n²) → O(n)

`buildSnapshot` 原实现中，每个元素通过 `querySelectorAll('*')` 反向定位以生成 `ref`，整体为 O(n²)。
M4 改为在遍历时直接计算元素指纹生成 `ref`，并同步构建 `ref -> element` 映射，整体降为 O(n)。

- 优化前：200 元素页在 jsdom 中执行 300 次基准即超时（>120s）。
- 优化后：同一遍历逻辑可在线性时间内完成。

## 快照缓存

`snapshot` 引擎基于「URL + title + 元素 ref 签名」计算页面版本，`sinceVersion === 当前版本` 时返回空元素列表（缓存命中），避免重复解析整页。

## 可复现基准

运行：`npx tsx bench/snapshot-bench.ts`

| 指标 | 数值 | 说明 |
|---|---|---|
| 页面规模 | 50 交互元素 + 100 文本节点 | jsdom 受控规模 |
| 样本数 | 50 | 预热 10 轮 |
| 中位数 | ~150 ms | jsdom 环境 |
| P95 | ~167 ms | jsdom 环境 |

## 重要限制

- **jsdom 的 `getComputedStyle` 开销远高于真实浏览器**，且 `isVisible` 需沿祖先链查询显式隐藏样式，导致 jsdom 数值被样式计算主导，**不代表真实浏览器性能**。
- 真实浏览器 P95 目标（快照 ≤ 1s、简单操作 ≤ 300ms）需在目标浏览器（Chrome/Edge）中以本机实测，页面业务耗时单列。
- 本报告的价值在于记录「O(n²)→O(n)」的确定性优化与可复现的测量方法，而非绝对毫秒数。

## 容量限制（M4 已实现）

| 项 | 限制 |
|---|---|
| 快照元素上限 | 5000（超出截断并标记 `truncated`） |
| 请求速率 | 每会话 50 次/秒，桶容量 100（超限 `RATE_LIMITED`） |
| 批量 | 逐项结果，遇错停止，高风险动作阻断并单独提交 |
| 事件缓存 | 每会话最多 1000 条（超出截断，序号缺口可检测） |
